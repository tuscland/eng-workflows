# Finalize Parent

```text
/finalize-parent <parent-issue-or-local-run>
```

The calling agent authors cleanup and coordinates delivery. This workflow explicitly requests review subagents. Read the [local loop contract](../implement-ticket/references/local-review-loop.md) for upstream composition, persisted state, correction counting, human-decision criteria, publication conditions, native issue association, and the PR review record. The references below own cleanup selection, evidence reuse, report delivery, and parent review mechanics; this entrypoint defines their sequence.

Invocation authorizes opening or updating the integration draft PR, bounded cleanup within the delivered parent scope, isolated end-to-end testing, an HTML delivery report, local commits, and publication of the independently reviewed result. Apply the shared human-decision criteria and continue independent work while awaiting guidance. Never merge PRs, close issues directly, mark the PR ready for review, or file cleanup tickets without separate authorization.

## Workflow

1. **Resolve the delivery and resume state.** Read repository conventions, the parent's authoritative specification, native child tree, and planning handoff. Resolve the canonical parent, integration branch, original target branch, planning baseline, and artifacts; fetch both branches. Reuse the integration worktree and existing `parent-finalization` run, or create its worktree under `.worktrees/` if absent. Preserve uncommitted work and reconcile unexpected branch changes. Resolve missing handoffs rather than assuming `main`.
2. **Verify child delivery.** Enumerate all children, including nested and closed issues, with pagination. Read associated PR bodies, review records, relevant discussion, changed files, merge state, and base. Match canonical issue identities through native relationships and explicit handoffs. Verify each required child's recorded merge/squash commit and resulting code are present; an open issue may already be delivered. Record superseded PRs and approved exclusions. Missing, unmerged, or reverted required work, missing acceptance criteria, and unresolved child decisions prevent completion; do not merge, cherry-pick, or drop children to bypass them.
3. **Open or reuse the integration draft PR.** Use already-pushed integration history against the declared target. Record its URL immediately and describe the parent outcome, included child PRs, and pending cleanup/review. Reconcile an existing non-draft or merged PR before changing it; avoid duplicates. Keep the draft if later work is blocked.
4. **Select cleanup.** Follow [Cleanup selection](references/cleanup-selection.md) to assess child proposals against the combined code and choose supported, bounded work. Execute worthwhile selections; if none merit execution, record why and continue.
5. **Implement and establish evidence.** Read [End-to-end testing and delivery report](references/delivery-report.md), then run `/implement` for selected cleanup under the shared composition contract. Pass its evidence-reuse policy to implementation and review agents. Preserve acceptance criteria, record the resulting candidate and checks, and run required integration checks. Establish end-to-end coverage and produce the self-contained HTML demonstration and code explanation under that reference. These deliverables are required even when no cleanup is selected.
6. **Review and correct.** Follow [Parent review](references/parent-review.md) for the parent run, full review scope, specialist delegation, and correction handling. Apply the shared review/fix loop and its ten-correction limit. Supported fixes go through `/implement`; rebuttals carry evidence. Refresh evidence and the report under the report reference's reuse policy before returning to review.
7. **Publish the reviewed result.** Apply the shared publication conditions and the report reference's completion requirements. Push reviewed history and update the existing draft with the delivery summary, validation, cleanup dispositions, remaining debt, report summary/link, and final review record. Add closing directives and verify native associations under the shared procedure for the parent and every delivered child whose criteria are satisfied, including nested children. Exclude deferred, cancelled, and unrelated tickets; report deferred automatic closure if the target is not the default branch.
8. **Verify and hand off.** Verify the remote head, target, body, issue associations, and required PR checks for the published SHA. Pending or failed required checks leave finalization incomplete; resume that phase. Code fixes return through the same correction budget and review. Deliver the report under its artifact rules, adding only permitted final status updates after clearance. Report the clickable HTML artifact, draft PR, delivered children, cleanup and deferred opportunities, human decisions, checks, correction/review counts, commit, and local run path. Retain the worktree, report, and evidence. Finalized means ready for the user's merge decision.
